HomeLab AI Stack I chained three computers together so my AI never goes offline. 10
MLOps / AI Infra · Feb 2026 – May 2026
Why Build It?
Cloud AI APIs are powerful, but they come with three problems: unpredictable costs, data leakage risks, and service outage when the network drops. I wanted to build a private, low-cost, highly available AI inference environment.
So I connected my Mac M4, an old laptop, and a mini PC together — using Tailscale for networking, LiteLLM for load balancing, and a 3-tier fallback mechanism. If the smallest model goes down, the medium one takes over. If that also fails, the Cloud API catches it. AI stays online, always.
  • Supervisor-Worker tiered architecture with heterogeneous device integration
  • 3-Tier Fallback: 4B → 35B → Cloud API
  • Full MLOps monitoring: Prometheus + Grafana + Telegram alerts
  • 23 ADRs documenting every technical decision

TW Stock Gift Evaluator From 500 Lines to 200 — The Refactoring Journey 23
Refactoring
Good code is code that future you will thank you for
The initial version hardcoded all business logic in 500 lines of Python. Every time a new gift type was added or scoring rules adjusted, the core code needed modification — high testing cost, high error risk.
After refactoring, a JSON tree structure with a Depth-First Search (DFS) algorithm replaced the hardcoded logic. Business rules and code are fully decoupled — adding new rules only requires editing a JSON file, no core code changes needed.
  • Code reduced by 60%, readability significantly improved
  • New rule addition time reduced from 2 hours to 10 minutes
  • Business logic fully decoupled from knowledge base
  • Serverless architecture ensures near-zero monthly maintenance cost

SynthForge Architecture — Stateless Skills + YAML Workflow 25
Architecture
Good architecture makes complexity simple
Using a stateless Skills + stateful Agents design pattern, paired with a YAML declarative workflow engine. Skills are reusable functional modules, Agents are executors with memory and decision-making capability, and workflows define how they collaborate.
  • Stateless Skills: Pure functional modules, testable and reusable
  • Stateful Agents: With context and decision-making capability
  • YAML declarative workflows: Configuration over code, reducing maintenance cost
  • Highly decoupled: Adding new Skills doesn't affect existing Agents
